# Footman local API v1

**Experimental until Footman 1.0** (ADR-0018). Methods and payloads may still change; changes are recorded in ADRs.

The daemon (`footman daemon`) serves JSON-RPC 2.0 to local clients. The `footman` CLI commands `status`, `say`, `stop` and `events` are clients of this API; anything they do, another client can do. Wire details are in ADR-0025.

## Connecting

- **Socket:** `$XDG_RUNTIME_DIR/footman.sock` on Linux (`/tmp/footman-<uid>/footman.sock` when `$XDG_RUNTIME_DIR` is unset). `footman status` prints the path in use; `$FOOTMAN_SOCKET` overrides it for the daemon and the CLI. The path must fit the OS's socket address: at most 107 bytes on Linux and 103 on macOS and the BSDs. The daemon refuses a longer path before it starts, and says how long it is and what the limit is.
- **Access:** the socket is `0600` and its directory `0700`, so only the user who runs the daemon can connect. There is no other authentication on the socket.
- **Framing:** one JSON value per line, ending in `\n`, in both directions. A line may hold a request, a notification or a batch array. Lines over 1 MiB close the connection.
- **Order:** requests on one connection run concurrently; match responses by `id`.

Try it by hand:

```sh
echo '{"jsonrpc":"2.0","id":1,"method":"status.get"}' | socat - UNIX-CONNECT:$XDG_RUNTIME_DIR/footman.sock
```

## Errors

Errors use the JSON-RPC `error` object. Codes:

| Code | Meaning |
|---|---|
| -32700 | Parse error: the line is not JSON |
| -32600 | Invalid request |
| -32601 | Method not found |
| -32602 | Invalid params (including unknown members) |
| -32603 | Internal error |
| -32000 | The method ran and failed; `message` says why |
| -32001 | Busy: another utterance is being handled |
| -32002 | Not found: no such job, subscription or config key |
| -32003 | Unavailable in this daemon |

## Methods

### `status.get`

No params. Result:

```json
{"version":"0.1.0","api":"v1","pid":4242,"started_at":"2026-11-25T09:00:00Z","uptime_seconds":90.5,
 "state":"idle","muted":false,"microphone":{"state":"on"},"jobs":["job-1"],"dev_fakes":false,
 "implementations":{"platform":"linux","stt":"whispercpp","vad":"silero","wake":"sherpa","tts":"persona","llm":"claude","worker":"claude-code"},
 "socket":"/run/user/1000/footman.sock","config":"/home/me/.config/footman/config.toml",
 "models":{"unload_after":"10m0s","models":[{"name":"stt","engine":"whispercpp","loaded":true,"since":"2026-11-25T09:00:02Z","loads":1,"in_use":0}]}}
```

`models` says which speech models (`stt`, `vad`, `tts`) are in memory (ADR-0028): `unload_after` is `speech.unload_after` (`"0s"` means never), `since` is when the model was last loaded or unloaded, `loads` counts loads, and `in_use` is how many callers hold it now. A model that is not loaded is loaded again on its next use.

`state` is the pipeline state (see `pipeline.state` below). `muted` is true after a stop. `microphone.state` is what the microphone loop is doing: `on` (the wake word is listening); `push_to_talk` (no wake word: the microphone is closed and opens only while a push-to-talk key records); `recording` (a push-to-talk key is recording now); `muted` (after a stop); `off` (not started, because there is no VAD); or `stopped`, in which case `microphone.error` says why it stopped (for example no hotkey could be registered, or a microphone that went away). An empty implementation name means that area is not available.

`dictation`, present only while a voice-started dictation session runs, is `{"phase", "message", "target"?}` (see `dictation.status`).

`hotkeys` lists the push-to-talk keys, `[{"action":"dictate","key":"F8","mode":"hold"}]`; `mode` is `hold` or `toggle` (tap to talk), and `error`, when present, says why that key could not be registered. `last_dictation`, once something has been dictated, is `{"at", "chars", "method", "latency_ms"}`: when, how many characters, `type` or `paste`, and the time from the key coming up to the text being inserted. It never includes the text (ADR-0030).

### `events.subscribe`

Params: `{"topics": ["pipeline.state", "jobs.*"], "buffer": 256}`, both optional. A topic is a name, a prefix ending in `.*`, or `*`; no topics means all. `buffer` is how many events may wait for this client before newer ones are dropped. Result: `{"subscription": "sub-1"}`.

Events then arrive as notifications:

```json
{"jsonrpc":"2.0","method":"event","params":{"subscription":"sub-1","topic":"pipeline.state","seq":12,"at":"2026-11-25T09:00:01.5Z","data":{"from":"idle","to":"routing","turn":1}}}
```

`seq` increases across all topics in the daemon; a gap means events were missed (a slow client) or belong to topics you didn't subscribe to.

### `events.unsubscribe`

Params: `{"subscription": "sub-1"}`. Result: `{}`. Subscriptions also end with the connection.

### `say.text`

Params: `{"text": "open youtube", "as": "command"}`. `as` is `command` (default), `dictate` (insert the text at the cursor, with cleanup) or `wake` (as if spoken after the wake word: "stop everything" is then the break-glass stop). Returns `{}` once the pipeline is idle again; background jobs it started keep running. Fails with -32001 while another utterance is being handled, and with -32000 if a stop cancels it.

### `jobs.list`

No params. Result: `{"jobs": [{"id": "job-1", "status": "running"}]}`, the jobs that have not finished. Statuses: `queued`, `running`, `succeeded`, `failed`, `cancelled`.

### `jobs.cancel`

Params: `{"id": "job-1"}`. Result: `{}`. Watch `jobs.update` for the final status.

### `config.get`

Params: `{"key": "dictation.insert"}` returns `{"key": "dictation.insert", "value": "auto"}`. Without a key, returns `{"values": {"dictation.insert": "auto", ...}}` with every set value. Secrets appear only as references (`"keychain:claude"`).

### `config.set`

Params: `{"key": "dictation.insert", "value": "paste"}`. The value must have the key's type (see `config.schema`). The config file is edited in place, keeping comments. Result: `{"key": "...", "value": ..., "reload": "live"}`; `"restart"` means the daemon must be restarted for the change to take effect. Invalid keys or values fail with -32602.

### `config.schema`

No params. Result: `{"keys": [{"path": "dictation.insert", "type": "string", "default": "auto", "description": "...", "enum": ["auto","type","paste"], "voice_settable": true, "reload": "live", "security_sensitive": false}, ...]}`.

### `system.stop_everything`

The break-glass stop (ADR-0017): cancels every job and in-flight request (and any speech) and mutes the microphone. No params. Result: `{"jobs": ["job-1"], "turns": 1}`, what was cancelled.

### `speech.transcribe`

Params: `{"path": "/home/me/clip.wav", "vad": true}`. Runs a WAV file (any rate, channels and PCM encoding; converted to 16 kHz mono) through the daemon's own VAD and speech-to-text engines, outside the pipeline: nothing is typed, run or published as an event. `path` must be absolute and readable by the daemon. With `"vad": false` the whole file is transcribed at once. A diagnostic and benchmarking aid (ADR-0027); `footman transcribe FILE.wav` calls it. Result:

```json
{"text":"When we were out in the darkness of the quadrangle, we again looked up at the windows.","language":"en",
 "segments":[{"start_ms":550,"end_ms":5000,"text":"When we were ...","stt_ms":98.2}],
 "duration_ms":5000,"vad_ms":22.4,"stt_ms":98.2,"total_ms":121.9,"stt":"whispercpp","vad":"silero"}
```

`stt_ms` per segment is the time from the end of that utterance to its text. Fails with -32003 when the daemon has no speech-to-text engine, or no VAD and `vad` is not false; with -32602 for a relative path or a file that is not a WAV; with -32000 if the engine fails.

### `actions.list`

Params: `{"limit": 20}` (default 20, at most 1000). Returns the latest action-log entries, newest first (ADR-0038):

```json
{"actions":[{"id":12,"at":"2026-11-26T10:00:00Z","actor":"owner","action":"tool","tool":"open_url",
  "args":"{\"url\":\"https://go.dev\"}","result":"opened https://go.dev","confirmation":"auto","reason":"open go dev"}]}
```

`actor` is `owner` (spoken, until speaker recognition ships) or `api` (a socket client). `action` is `tool` (an AI tool call), `fast_path` (a command handled without the AI; `tool` names the rule) or `setting` (`tool` is the key and `args` is `"old → new"`). `args`, `result` and `reason` (the request that led to it) have secrets redacted. `confirmation` is `auto`, `click`, `voice`, `policy` (refused, or allowed with nothing to ask, by the `[permissions]` policy) or `timeout`; a refused action has a `result` starting with `error: refused`. Fails with -32003 when the daemon has no action log; `footman actions [-n N]` calls it.

### `confirm.list`

No params. Returns the confirmations waiting for an answer, oldest first (ADR-0039):

```json
{"requests":[{"id":"2","kind":"setting","level":"act","title":"Change permissions.action_log?",
  "detail":"permissions.action_log: true → false","reason":"asked by voice, and it can't be changed by voice because it affects security or permissions",
  "click_only":true,"asked":"2026-11-26T10:00:00Z","expires":"2026-11-26T10:02:00Z"}]}
```

`kind` is `tool` (the permission gate asks before a tool or fast-path action runs; `level` is its permission level) or `setting` (a setting change asked for by voice that loosens security). `detail` shows exactly what would run or change, **unredacted**. `click_only` requests are never answered by voice. Unanswered requests are refused at `expires` (2 minutes). Fails with -32003 when the daemon has no confirmations; `footman confirm` calls it.

### `confirm.answer`

Params: `{"id": "2", "allow": true}` (both required). Allows or refuses a pending confirmation; returns `{"id": "2", "allowed": true}`. A socket client is the owner at the keyboard (ADR-0025), so its answer counts as a click, also for `click_only` requests. A setting change is applied as asked shortly after Allow, and reported on `settings.changed` with `how` `click`. Fails with -32002 when no pending request has that ID (never asked, already answered, expired or withdrawn), -32602 without `id` or `allow`, and -32003 when the daemon has no confirmations. `footman confirm allow|deny <id>` calls it.

## Event topics

| Topic | `data` |
|---|---|
| `pipeline.state` | `{"from", "to", "turn"}`. States: `idle`, `listening`, `transcribing`, `routing`, `cleaning`, `inserting`, `acknowledging`, `fast_path`, `thinking`, `running_tool`, `replying`. `turn` numbers the utterance (0 when none). |
| `pipeline.transcript` | `{"turn", "trigger", "text", "audio_ms", "stt_ms"}`; trigger is `wake`, `dictate` or `command`; `audio_ms` and `stt_ms` (the speech's length and how long speech-to-text took) are absent for text that was not spoken |
| `pipeline.route` | `{"turn", "route", "text"}`; route is `dictation`, `command` or `none` |
| `pipeline.inserted` | `{"turn", "text", "method", "latency_ms", "insert_ms"}`; method is `type` or `paste`; `latency_ms` is from the push-to-talk key coming up to the insertion finishing (absent when the text did not come from a key) and `insert_ms` how long typing or pasting took |
| `pipeline.fast_path` | `{"turn", "rule", "error"?, "reply"?, "confirmation"?}`; `confirmation` is how the permission gate decided (`auto`, `click`, `voice`, `policy`, `timeout`); a refused rule did not run and has `error` |
| `pipeline.tool` | `{"turn", "name", "args", "result", "is_error", "confirmation"?}`; `confirmation` as for `pipeline.fast_path` (absent for an unknown tool) |
| `pipeline.reply` | `{"turn", "text"}` |
| `pipeline.error` | `{"turn", "state", "error"}` |
| `pipeline.wake` | `{"keyword", "at_ms"}`: the wake-word spotter fired; `at_ms` is where the wake word ended in the microphone stream. With `speech.wake.verify` the turn that follows still has to pass the speech-to-text check (ADR-0041). |
| `pipeline.wake_rejected` | `{"turn", "reason", "audio_ms", "stt_ms"}`: the speech-to-text check dropped a wake because the transcript did not start with a wake word (`reason` `no_wake_word`) or was empty (`no_speech`). The text is not sent. |
| `pipeline.outcome` | `{"turn", "trigger", "route", "handler"?, "error"?}`: how a routed turn ended. `handler` is what acted on a command: a fast-path rule's name, `ai`, or `no_ai` (no rule matched and there is no AI provider). `error` is set when it failed (`context canceled` after a stop). Turns of a voice-started dictation session (ADR-0045) have trigger `dictate`; their `handler` is empty for typed text, or `dictation_stop`, `dictation_edit`, `dictation_edit_blocked`, `dictation_edit_unsupported`, `dictation_pick` or `break_glass` for a command. No text. |
| `pipeline.stop` | `{"source", "jobs", "turns"}`; source is `voice`, `hotkey` or `call` |
| `pipeline.mic` | `{"mic"}`: `off`, `wake_listening` or `recording` |
| `dictation.status` | `{"active", "phase"?, "message", "target"?, "reason"?}`: a voice-started dictation session (ADR-0045) started, changed phase or ended. `phase` is `dictating` (every utterance is typed, no wake word) or `choosing` (waiting for a number to pick one of several files). `message` is the status to show, such as `Dictating — say 'stop dictation'`; `target` is the file being dictated into. When `active` is false the session ended and `reason` is `stop_phrase`, `idle`, `stopped` (break-glass), `microphone`, `listening_off`, `cancelled`, `error` or `shutdown`. |
| `confirm.request` | A confirmation is waiting for an answer: the same object as an entry of `confirm.list`. A UI shows it with Allow and Deny and answers with `confirm.answer`. |
| `confirm.resolved` | `{"id", "allowed", "how"}`: a confirmation ended. `how` is `click` or `voice` for an answer, `timeout` when it expired unanswered (refused), or `cancelled` when the task that asked was cancelled or the daemon stopped (refused). |
| `settings.changed` | `{"key", "old", "new", "actor", "how", "reason"}`: a setting changed by voice (`how` `voice`), by voice and then a click on its confirmation (`how` `click`), through `config.set` (`actor` `api`) or by editing the config file (`reason` `config file edited`). Values are in file form; secrets appear only as references. |
| `jobs.update` | `{"id", "prompt", "status", "message", "at"}` |
